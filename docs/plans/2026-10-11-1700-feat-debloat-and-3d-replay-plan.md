# Debloat (drop PyTorch) and 3D Replay View - Plan

## Goal Capsule

- **Objective:** Make the deploy light enough for a 0.1-CPU / 512 MB free instance, and show the creature in 3D.
- **Means:** Replace PyTorch with NumPy for the 324-parameter brain, keep pygame/matplotlib out of the server image, precompute a replay of the best walker, and render it client-side with Three.js.
- **Product Authority:** User request 2026-10-11 ("remove all the bloating", "let's do it" on record-once replay + Three.js 3D view). Follows `docs/plans/2026-10-11-1612-feat-render-deploy-and-cleanup-plan.md`.
- **Open Blockers:** None.

---

## Product Contract

### Problem Frame
Measured installed sizes: torch 478 MB, pygame 31 MB, matplotlib 30 MB, numpy 31 MB, pymunk 1.8 MB, flask 0.7 MB. The brain is a 15→16→4 tanh MLP (324 floats), and torch is used only for that forward pass, `state_dict` save/load, and mask/noise ops in crossover/mutation. NumPy does all of that. STRATEGY.md already positions the project as "without heavy ML dependencies". Separately, every dashboard viewer makes the server simulate a full episode and stream about 45 JSON frames per second. The best model is deterministic, so that's the same episode on a loop, recomputed per viewer.

### Requirements
- R1. No `torch` import anywhere; `torch` removed from requirements, pyproject, and Dockerfile.
- R2. Checkpoints stored as `.npz` (same file names, new extension). Existing `models/*.pth` converted once, then deleted. The converted universal best reproduces the exact same rollout as before (same fitness, same final x).
- R3. Brain math unchanged: same architecture, `tanh` both layers, init `N(0, 0.25)`, same mutation (per-param mask at `mutation_rate`, Gaussian noise × `mutation_scale`) and uniform crossover. float32.
- R4. The server image installs only what `app.py` needs (flask, gunicorn, numpy, pymunk). pygame and matplotlib move to an optional/dev install; `main.py` imports pygame lazily so `train()` works without it.
- R5. A recorded replay of the universal best (one episode of render frames) is generated by a script and served as a static file. The dashboard plays it client-side, with no per-viewer simulation on the server. The live SSE endpoint stays for local use / training.
- R6. The dashboard renders the replay in 3D with Three.js: extruded torso/leg boxes, ground, lighting, follow camera, frame interpolation. Keep the brutalist/high-contrast brand (STRATEGY.md), stay accessible (canvas label, reduced-motion respected), and keep a 2D fallback if WebGL is unavailable.

### Scope Boundaries
- No real 3D physics (MuJoCo port is v3/v4 work).
- No change to physics, reward, or GA hyperparameters.

## Planning Contract

### Key Technical Decisions
- KTD1. `CreatureBrain` becomes a plain class holding `w1 (16×15), b1 (16), w2 (4×16), b2 (4)` float32 arrays, keeping the `nn.Linear` weight layout so conversion from the old `state_dict` (`net.0.weight`, `net.0.bias`, `net.2.weight`, `net.2.bias`) is a direct copy. It keeps the `get_action`, `state_dict`, `load_state_dict`, and `parameters()`-style access the rest of the code uses, so call sites barely change. (R1-R3)
- KTD2. Save with `np.savez`, written atomically via temp file + `os.replace` (rename `atomic_torch_save` → `atomic_save`). (R2)
- KTD3. Replay = JSON array of the existing `get_render_state()` frames, rounded to 2 decimals, at `models/universal_best_replay.json` (or similar), regenerated by `scripts/record_replay.py` and committed. (R5)
- KTD4. Three.js from cdnjs, pinned version, no build step. (R6)
